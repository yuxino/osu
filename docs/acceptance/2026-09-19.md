## Build 5 — feedback from actual phone use

- The user reported inaccurate translation, inability to enlarge webpage video after opening Osu, and unclear missing-broadcast guidance. Build 4 session `1A9A3F0A-2191-4280-AB9A-E2084A4FBBC9` selected Apple **en-US → zh-Hans** while the user said the video was Japanese. It recorded 272.41 audio seconds, 11 recognition updates and 3 translation updates, with nonzero peaks earlier in the session. A last sampled zero peak did not mean the whole session was silent. The extension recorded 898 dropped chunks. No original audio or transcripts were retained, so exact incorrect words were not diagnosed.
- Build 5 defaults to Alibaba automatic input → Chinese. A one-time migration removes the demo's implicit English/Japanese source hint; later manual choices persist. Apple local mode remains an explicit manual-source option. Choosing the same Apple source/target switches to original-only.
- Idle/stopped preview now uses labels without creating a PiP controller, timebase or sample-buffer layer. The previous `showStill()` enqueued live frames even on opening the page. Audio/PiP now activate only after an authenticated broadcast connection. This removes confirmed premature media setup; it is not by itself proof that every webpage fullscreen flow is fixed.
- Start opens a dedicated system broadcast guide automatically. Cancel stops the prepared connection. Live state derives from authenticated transport, one-second extension heartbeats, PCM arrival and recent sound level; silence is distinct from no broadcast. A six-second lost heartbeat ends the stale session. Snapshots name capture state explicitly and are never used as current permission evidence.
- Extension audio is bounded to two seconds and batched near 100 ms. Host delivery also buffers instead of discarding audio while the main thread is busy. Overload stops with an explicit message. A 4,000-chunk uneven/backpressure fixture preserved every PCM byte; host tests retained 1.5 seconds in order, re-armed the drain and rejected stale delivery after cancellation. These checks do not substitute for physical ReplayKit throughput evidence.
- State-transition and language-migration checks passed. The simulator verified idle preview creates no media and stop releases it; opening the production controller left audio category/mode unchanged. Actual UI checks showed automatic → Chinese, the immediate authorization guide, and cancellation returning to an enabled Start button with no active socket, audio or PiP. The guide uses Apple's public RPSystemBroadcastPickerView; no private selector or synthesized authorization is used.
- Signed Release build 5 and deep signature verification passed. Physical update and remaining cross-app/fullscreen checks are tracked separately below.
