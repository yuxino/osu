# Osu builds 12–14 — lyrics and everyday settings

## Build 12 changes

- The previous lyric has enough vertical space at the largest accessibility text
  size. Long text still keeps a readable tail, with whole short English words
  where possible. Tail fitting now searches trim boundaries instead of measuring
  every discarded prefix on every animation frame.
- Cancelling capture before any audio or text arrives restores the idle subtitle
  preview instead of leaving it saying that translation is pending. Stopping after
  receiving text still preserves the last line.
- Home explains the accepted flow: start subtitles, then return to the original
  video app. Automatic input → Chinese remains the initial language choice.
- Settings keeps service and credential state visible. Usage/privacy and
  checks/diagnostics expand on demand; Done stays above the scrolling content.
  Local-language checks appear only for Apple. Existing keys, preferences, bundle
  IDs, capture permission and billing behavior are unchanged.

## Renderer regression

The isolated simulator harness renders authored text with the production
`LyricsPainter`, saves PNGs, and checks the previous/current/original text bands.
The simulator's actual content-size preference is used, rather than assuming a
local trait override changes UIFontMetrics. Images use standard 32-bit range for
pixel inspection. The before/after measurements below cover 30 transition frames
on this Mac; they are **not iPhone performance measurements**.

| Case | Before | After |
| --- | --- | --- |
| Largest text, previous lyric | No visible pixels | Visible for short and long text |
| Largest text, long sentence median / p95 | 23.90 / 31.22 ms | 1.96 / 2.12 ms |
| Regular text, long sentence median / p95 | Not measured | 1.97 / 2.24 ms |

The corrected test reproduced the missing previous line at 17:02:26 UTC on
September 19. It passed at largest size at 17:08:28 UTC and regular size at
17:10:30 UTC. The resulting PNGs were visually inspected. Local evidence:
`.build/lyrics-usability/before-accessibility/`, `after-accessibility/`, and
`after-regular/`.

## Interaction checks

- Operated the production controller inside **Osu Tests** using the computer's
  accessibility controls. The settings sections start collapsed, diagnostics
  expands, Apple hides Alibaba-only checks and exposes local-language refresh.
- The largest text size displays credential state and an available Done button.
  Usage/privacy expands and Done returns to the home screen. The simulator's
  preferred size was restored to `large` afterward.
- After the final cancellation-preview fix, the 45-second permission-wait,
  resume, cancel/restart, authenticated PCM and finish regression passed at
  17:35:52 UTC. It explicitly checked that cancelling an empty session restores
  the idle preview while stopping a session with received text preserves it.
  Both production packages were rebuilt after that change.
- Pointer-based scrolling still returns `noWindowsAvailable` from the computer
  control tool. This is a tool failure; direct scroll-gesture acceptance remains
  open. Accessibility actions do not substitute for a successful scroll gesture.

## Paced synthetic stream

The separate harness uses authenticated loopback PCM, the production receiver,
cloud client, controller and lyrics painter, with in-memory provider replies and
an injected dummy credential. It sends one 3,200-byte PCM chunk every 100 ms,
produces drafts and finals with advancing IDs, then confirms the final tail.
No real service credential or paid provider request is used.

- The 12-second smoke check passed at 17:13:55 UTC: 120 chunks, 384,000 PCM bytes,
  13 updates per language and five final results per language, including the
  closing sentence. Capture and provider sockets closed, stopped state was saved,
  and media was released.
- The 15-minute run passed at 17:30:10 UTC: 900.08 elapsed seconds, exactly
  9,000 received/sent chunks and 28,800,000 PCM bytes, 901 updates per language
  and 301 final results per language including the closing sentence. The renderer
  submitted 5,386 frames. One finish request completed; both sockets closed,
  capture state became stopped, media was released and the last line stayed
  visible. The actual screen returned to an enabled Start button.
- Twenty-nine process samples span 17:16:16–17:30:17 UTC. RSS varied from
  154.91–231.56 MiB (222.17 first, 218.66 last), without sustained growth over
  this interval; CPU time averaged about 5.16% of one Mac core. These measure
  the isolated native harness, excluding the React Native shell, and say nothing
  about iPhone memory, power or battery. Maximum synthetic send lateness was
  76.01 ms; it is not provider latency.
- Complete results and resource samples are retained locally under
  `.build/lyrics-usability/stream-endurance/`; the smoke run has its own folder.

## Build and remaining acceptance

Native core checks and TypeScript checking passed. Signed iPhone Release build 12
passed deep signature verification. The full simulator Release build also passed;
host and broadcast extension in both packages report 1.0.0 (12). Native source
copies in the generated iOS project match the reviewed files. The build retains
existing AVSampleBufferDisplayLayer deprecation warnings; no new compile error
was introduced. The full Release build was installed over the existing simulator
app and visibly launched. Home retained automatic input → Chinese; settings
showed the existing key as configured, opened/cancelled secure editing without
changing it, and expanded diagnostics. Start opened the capture guide and
Cancel returned to idle without starting a provider connection. Screenshots are
`.build/lyrics-usability/release-home.png` and `release-settings.png`.

The user took the phone away; this work does not contact, install on or operate it.
The phone has not accepted build 12. Real Bilibili/ReplayKit continuity, long-run
cloud latency/accuracy, battery behavior and competing PiP remain separate gates.
The current simulator reports PiP unsupported, so the synthetic stream cannot
establish cross-app overlay behavior. Independent video and subtitle PiP windows
still cannot coexist.

## Build 13 — optional original text

Translations now appear alone by default. Settings has a **显示原文** switch;
changing it refreshes the preview and active sample-buffer renderer, and the
preference is saved across launches. The translation uses the space released by
the hidden original. Hidden text is also omitted from the accessibility value.
Apple recognition-only mode keeps its source text readable and disables this
secondary-text option until a translation language is selected.

- The production painter passed short/long, bilingual/translation-only cases at
  regular and maximum accessibility sizes (17:50:45 and 17:51:49 UTC on September
  19). Translation-only images have no source text pixels; current and previous
  lines remain visible. Resulting PNGs were visually inspected.
- Actual settings interactions in the isolated harness confirmed the switch
  starts off, immediately adds the Japanese source when enabled, and removes it
  when disabled. Both saved states survived app termination and relaunch.
- The updated 12-second paced stream passed at 17:55:38 UTC: 120 PCM chunks,
  384,000 bytes, final text retained, both connections closed and media released.
  It uses authored input and in-memory replies, not a live cloud provider.
- With the simulator's real Reduce Motion preference off, a new sentence
  submitted 13 frames over 0.66 seconds. With it on, it submitted two over 0.64
  seconds (17:48:10 and 17:58:41 UTC). Both retained the last line and released
  media after stopping. Reduce Motion was restored to off, and text size to
  `large`. These are simulator checks, not phone performance measurements.
- Native core and TypeScript checks passed. Both full Release packages built;
  the signed iPhone app passed deep signature verification. Host and broadcast
  extension report 1.0.0 (13). The simulator Release app was installed and opened;
  settings visibly showed **显示原文** off. Local results and screenshots are in
  `.build/original-visibility/`.

The phone has not been updated to build 13. PiP dimensions and its single-window
occupation are unchanged; hiding original text does not resolve competing video
PiP. The simulator still cannot verify the real cross-app floating window or
changing its text visibility during phone playback.

## Build 14 — Osu caption style

- The approved character mark and serif Osu wordmark sit in the context row.
  Captions use a flat near-black background and left-aligned text. The translation
  keeps the full text width; the character is decoded once into a 160-pixel image.
- New sentences settle upward by 24 canvas pixels over the existing 360 ms
  transition. Previous/current/original text stays in separate bands, including
  during long-sentence transitions. Incoming text stays visible throughout.
- All four regular and maximum-size renderer cases passed at 18:08:14 and
  18:08:52 UTC on September 19. Checks include the actual bundled character,
  visible previous/current lines and absent hidden-original pixels. Full-size,
  240 × 110, and transition PNGs were inspected. Regular long-text render p95 was
  about 2 ms on this Mac; this is not a phone performance claim.
- Actual Reduce Motion off/on checks passed at 18:10:20 and 18:12:12 UTC: 13
  versus two submitted frames over approximately 0.65 seconds, retained text and
  released media after stop. The simulator preference was restored to off.
- The 12-second paced synthetic stream passed at 18:16:04 UTC: 120 chunks,
  384,000 bytes, one finish, closed sockets and retained final text. Native core,
  TypeScript and whitespace checks also passed.
- Both full Release builds passed and report 1.0.0 (14) for host and extension.
  The device package passed deep signature verification. Xcode optimizes the
  bundled PNG to CgBI, so source/package byte equality is not an appropriate image
  check. Both packages contain it; its appearance was confirmed in the full
  simulator app. Reviewed and generated native source copies match.
- The nine-second, 960 × 440, 30 fps clip uses the actual painter and illustrative
  text. It was decoded with AVFoundation and sampled for inspection. A frame is
  included in both READMEs and labelled as illustrative. The clip, reports,
  render frames and Release screenshot are retained under `.build/pip-style/`.

The phone was not contacted or updated. Physical PiP rendering, its temporary
system controls, real background capture and video-app interaction remain
unverified on this build. PiP dimensions, system controls and mutual exclusion
are unchanged. This is a visual update to the existing PiP surface.

## Re-run

After `bundle exec ruby scripts/configure-simulator-harness.rb`, on an already
booted simulator:

```sh
xcrun simctl ui SIMULATOR_UDID content_size accessibility-extra-extra-extra-large
scripts/test-simulator.sh SIMULATOR_UDID --verify-lyrics-layout 30
xcrun simctl ui SIMULATOR_UDID content_size large
scripts/test-simulator.sh SIMULATOR_UDID --verify-lyrics-layout 30
scripts/test-simulator.sh SIMULATOR_UDID --verify-stream-smoke 30
scripts/test-simulator.sh SIMULATOR_UDID --verify-stream-endurance 930
scripts/test-simulator.sh SIMULATOR_UDID --verify-capture-start 75
# Run with the matching actual Reduce Motion setting in Simulator Settings:
scripts/test-simulator.sh SIMULATOR_UDID --verify-motion 20
scripts/test-simulator.sh SIMULATOR_UDID --verify-reduced-motion 20
```

Keep the isolated harness foreground during the paced stream. Its report is
`Documents/stream-endurance.json`; the generic fresh pass/fail marker is
`Documents/simulator-test.json`. Fixtures are not linked into the shipping app.
