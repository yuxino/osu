# 语言、诊断与验证

## 当前实现

- 声音语言来自 `SFSpeechRecognizer.supportedLocales()`，保留地区差异；只有系统报告支持本地识别的项可选。开始时再次检查本地能力和当前可用性，所有请求都强制本地处理。
- “本地能力存在”不等于资源永远可用。运行时错误会记录，界面会说明。当前使用的 Speech 接口没有应用内语言包下载入口；不会假称已下载，也不会转为云端识别。
- 字幕语言来自 `LanguageAvailability.supportedLanguages`，不是硬编码支持列表。每次选定组合再检查 `installed`（已就绪）、`supported`（需下载）或 `unsupported`（禁止启动该翻译组合）。中文保留简繁区别。
- “仅显示原文”明确关闭翻译。即使翻译服务不可用，也可以选择此模式；本地识别本身仍须可用。
- 下载使用系统 `translationTask` / `prepareTranslation()` 的确认界面。取消或下载失败不当作成功。检查超时会显示重试提示。
- iOS 26 起使用下载后的 `TranslationSession`；iOS 18–25 仅开放原文模式。
- 会话和下载期间锁定语言选择；异步检查有版本标记，切换后的旧结果不再覆盖新选择。停止时取消翻译、识别、接收器与 PiP。

## 本地诊断

`Documents/MimiDiagnostics/events-0.jsonl` 为最新日志，`events-1…5.jsonl` 为更早记录。
每个文件最多 128 KiB；轮换后仍保留整条 JSON 记录。日志上限约 768 KiB / 进程。
`diagnostics.txt` 为最后一次手动导出的副本，最多约 768 KiB 加文件头；导出时覆盖此副本。
主 App 和广播扩展各有独立容器，合计上限约 3 MiB（含两份可能的导出副本），另有小型状态快照。
诊断目录不参与备份，文件在设备首次解锁后可供后台会话写入。

记录包括：

- UTC 时间、UUID 会话编号、唯一事件编号、进程序号、系统与 App 版本、host/broadcast 来源。
- 语言能力检查、权限、下载准备、接收器就绪与连接、首帧音频、音频间断、首次识别与翻译、识别重启、PiP、前后台切换、停止原因。
- 每约 5 秒的帧数、音频秒数、识别/翻译次数、峰值音量、音频间隔、翻译请求耗时和扩展丢帧/转换失败计数。
- 错误仅保存允许的域名和数字代码；未知域记为 `other`。不记录错误描述或 `userInfo`，避免夹带内容、路径或凭据。

**不记录原始音频、字幕、翻译内容、API 密钥或设备身份信息。** 不自动上传。
UI 上的复制与导出包含主 App 最近保留的记录，并非所有历史，也不包含另一个容器里的扩展日志。
存储失败会在报告头和快照中标记；当文件无法写入时不能保证诊断完整。

`Documents/probe-status.json` schema 2 含时间、会话编号、运行标记与计数。
它是保存的最后一次快照，不是远程心跳。App 被系统终止后可能仍显示 `running: true`；
下次进入原生页会把旧会话标成 `previous_interrupted_unknown_cause`，不臆断是崩溃还是系统回收。
主进程和扩展会话编号独立，通过时间与 host 连接记录比对。
扩展在尚未连接时的错误只在扩展容器；主 App 只能证明“未连接/未收到音频”，不能猜出系统原因。

### 从已连接且授权的手机读取

```sh
python3 scripts/collect-diagnostics.py --device YOUR_COREDEVICE_ID
```

脚本只尝试复制主 App 日志、快照和扩展日志到 `ios/diagnostic-exports/<UTC 时间>/`，
不启动或停止 App，不删除手机日志，不读取音频或其他 App。
需要手机连接/信任、系统允许的开发访问；必要时解锁。
扩展容器是否能直接访问由系统决定，失败会明确标为 unavailable，不能把缺少扩展日志解释为未运行过广播。
若容器访问不可用，仍可从 App 导出主日志。
**没有连接或授权时，电脑不能实时知道手机发生了什么。**

## 可重复的本地检查

```sh
npm run typecheck
scripts/test-native.sh
bundle exec ruby scripts/configure-ios-prototype.rb
bundle exec ruby scripts/configure-simulator-harness.rb
# 选择已安装运行时下的模拟器，并启动一次：
xcrun simctl list devices available
xcrun simctl boot YOUR_SIMULATOR_UDID
scripts/test-simulator.sh YOUR_SIMULATOR_UDID
```

核心测试编译真实的诊断、语言规则和网络解析代码，检查脱敏、容量、会话恢复、快照停止状态、
语言状态约束、简繁区别，以及拆包、错误凭据、非法/过大音频包。
模拟器 harness 编译生产原生控制器和接收器，通过真正的本地 TCP 连接分段发送已知 PCM，
检查帧数和样本值；产出新的 `Documents/simulator-test.json`。旧结果会先归档，避免误报。
Harness 不请求麦克风、不注入真实 Speech/Translation 结果，不包含在主 App。

## 最后交给用户的真机测试

新版需要先重新构建、签名并安装；目前手机上的旧版不会自动更新。

1. 打开原生页，查看声音语言列表；挑一个本地可用的非英语语言（如设备实际可用的日语）。选择中文目标，按提示下载；关闭下载后应重新检查成已就绪。没有该源语言时应明确显示不可用。
2. 开启小窗、Mimi Audio 广播，切到播放同一源语言的 App，连续观察原文与翻译。先测 2 分钟，再测 15 分钟，记录字幕是否停住或延迟明显增大。
3. 停止后换另一个源语言/目标语言，确认字幕来自新选择，没有残留上一会话内容。测试仅显示原文，翻译计数应保持为零。
4. 检查下载取消、不支持的组合、语音权限拒绝时提示准确，且不会声称正在正常翻译。
5. 分别通过关闭小窗和停止按钮结束；广播应退出，日志有停止原因，快照 `running` 为 false。
6. 复制或导出诊断，确认有该会话时间、语言、链路事件和错误代码，却没有听到的原文或译文。若意外退出，重开原生页后导出，并提供故障大致时间。
7. 之后把手机连接且授权给电脑，再运行采集脚本核对历史日志。这一步不要求当时故障仍在发生。

所有非英语语言的识别质量、语言包下载成功、跨 App 兼容、长期后台表现，仍须按上述真机步骤验收。
